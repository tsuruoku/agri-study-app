# 農業技術検定・個人用学習PWA 初版設計

作成日: 2026-11-17
状態: 簡素化したWebアプリ構成で進めることを承認済み。製品コードは未作成。
変更: 通常のHTTPS配信はアプリ本体だけ。教材と記録はファイルから端末内に保存し、
Macの常時配信・独自証明書・端末への証明書導入は不要。公開先の説明と承認は別途行う。

## 1. 目的と成功の姿

紙教材では取り組みにくい隙間時間に、Androidで野菜別の解説を読み、問題を解き、
知識の定着と学習時間の積み重ねを確認できるようにする。利用者は本人のみ。
試験合格の予測ではなく、登録した教材の学習を継続するための道具とする。

初版は、提供済みPDF内の解説・例題・根拠を確認した追加問題について、
初回準備後に通信なしで学習と記録ができることを成功条件とする。

## 2. 合意事項と今回の設計判断

利用者が決めた事項:
- 最初はAPKではなくPWA。Androidで利用し、オフライン対応する。
- 野菜別に解説から例題へ進む流れと、問題だけのランダム・カテゴリ混合演習を用意する。
- 達成率は知識の定着度。解説から作るオリジナル確認問題も追加する。
- 今日・累計・週・月・日別の学習時間を表示する。
- 承認済み画面案の構成を使い、提供PDFの範囲で最初の版を作る。
- 教材を他人に共有せず、個人で使う。

以下は実装のための設計提案であり、既に利用者が選んだ仕様とは区別する:
- 定着は「24時間以上あけた2回の正解」で判定し、誤答で判定をやり直す。
- 1回5問を基本とし、未確認・要復習・カテゴリを絞って演習できる。
- 教材は事前に整備したローカル教材パック、記録はIndexedDBで保存する。
- 初回導入は通常のHTTPSサイトからアプリ本体だけ取得し、教材は端末でファイルから読み込む。
- バックアップは教材・画像・学習記録を含むファイルとして手動保存する。

## 3. Approaches / 検討した方式

| 方式 | 利点 | 制約と判断 |
| --- | --- | --- |
| PWA | Chromeからホーム画面に追加でき、端末内で読書・演習・記録が可能。小さく改善しやすい | HTTPSでの初回導入とブラウザ保存の対策が必要。利用者が選択 |
| Android APK | Android専用の保存・ライフサイクル制御ができる | インストール許可や配布・更新の手間が増えるため初版では採用しない |

PWA内ではPDFをそのまま読む方式より、文章と問題を構造化する方式を採用する。
スマホ向けの改行、回答の非表示、問題別の定着記録が必要なため。
原本画像は根拠確認用に残すが、主な学習画面にはしない。

## 4. 対象教材と取り込み

原本: `スキャン_トマトからナス.pdf`。17 PDFページのスキャンで、見開きを含む。
紙面の開始はp.105、終わりはp.137。PDFページ番号と紙のページ番号を混同しない。
カテゴリは「野菜共通」「トマト」「キュウリ」「ナス」とし、含まれる範囲だけを対象にする。
冒頭の生産動向なども「野菜共通」に収め、教材範囲から黙って除外しない。
統計値は教材に記載された年の情報として表示し、最新情報と誤認させない。

取り込みは開発時の作業であり、初版に汎用PDF自動取り込み機能は作らない。
手順は、紙面対応表作成、ローカル文字起こし、図表切り出し、設問構造化、
原本照合、教材パック作成。外部OCR・外部AIサービスへの送信は別途承認なしに行わない。
ローカル処理を優先し、判読不能な箇所を推測で補完しない。
文字起こしにはmacOS Vision等の端末内OCRを使用してよい。OCR結果は下書きとし、原本照合を省略しない。

各解説を短い節に分け、文章・表・図・写真を保持する。表は可能ならHTMLにし、
横幅が必要な図表は拡大表示できる。原本は紙面単位に分割した画像で参照できるようにする。
原PDFは変更しない。参照は教材ID、PDFページ番号、紙ページ番号、領域を記録する。

教材に載る問題は「教材の例題」と表示する。出典の確認できないものを過去問と呼ばない。
追加問題は「オリジナル確認問題」と表示し、根拠の節・紙ページ・短い解説を付ける。
原則5択・単一正解。組合せ表も1つの選択肢として扱う。選択肢順は初版では固定する。
各解説節について確認できる主要知識を洗い出し、追加問題との対応表を残す。
問題数を先に水増しせず、正解が一意で根拠を確認できたものだけを登録する。

温度・単位・数値範囲・病害虫名・正解番号を原本と照合し、照合済み状態を持たせる。
教材の正解と本文が矛盾する場合は黙って修正せず、該当問題を保留して理由を記録する。
保留箇所は教材一覧に示し、学習可能な範囲と未整備の範囲を区別する。
全範囲の確認と保留の解決、または利用者による明示的な除外了承まで初版の教材整備完了としない。

## 5. 画面と学習フロー

画面基準は `.superpowers/brainstorm/36603-1794859244/content/screens-v3.html`。
アイボリーの紙面、葉の緑、トマト色のアクセント、見出しは和文明朝系を維持する。
外部フォント・画像CDNには依存せず、Androidで利用可能なフォントにフォールバックする。
画面案の3パネルは説明用。製品ではスマホで1画面ずつ移動する。

```text
ホーム
  ├─ ランダムに5問 → 演習 → 回答と根拠 → 次の問題 → 結果
  ├─ 野菜別に学ぶ → 野菜・節 → 解説 → 関連する確認問題
  ├─ 要復習 / 未確認 → 対象を絞った演習
  ├─ 学習記録 → 定着状況 / 日別の学習時間
  └─ 設定 → 試験日 / 教材管理 / バックアップ
```

ホームには今日・累計・今週・今月の時間、定着度、未確認数、要復習数、
前回の学習の続き、試験日までの残日数を表示する。未設定なら「試験日：未設定」。
試験日当日は「試験当日」、過去なら「試験日を過ぎています」。定着度とは別指標とする。
初回データは0時間、未確認から始め、画面案のサンプル数値は使わない。

教材ではカテゴリごとの節一覧と各節の解説を表示する。読んだだけでは定着度を上げない。
前回の節・スクロール位置、進行中の演習を保存して再開できるようにする。
演習は1問ずつ表示し、選択後に「回答する」を押して確定する。変更は確定前のみ可能。
確定後に正誤・正解・解説・教材への参照を表示する。同じ設問表示への連打は1回答とする。

演習の回答前は正解欄、原本全ページ、答えになる画像キャプションや代替テキストを表示しない。
問題画像は問題に必要な領域だけを切り出す。回答後の根拠表示から原本ページを開ける。
解説から問題へ戻る場合は元の回答状態を保持する。画像自体はオフラインでも拡大できる。
これは自習用の表示制御であり、端末内の正解データを技術的に秘匿する試験システムではない。
演習とは別の教材閲覧モードでは原本を自由に参照でき、例題の正解が載るページには開く前に注意を表示する。演習中の参照操作にはこの自由閲覧を組み込まず、回答後に原本を開く。

出題開始時にカテゴリ・対象状態・問題種別を絞り、対象集合から重複なしで無作為に最大5問選ぶ。
カテゴリ混合では全対象問題を同じ確率で扱う。必ず各カテゴリ1問ずつにはしない。
不足時は実数で開始し、0件なら理由と条件変更への入口を示す。
要復習は最新回答が誤答の問題、未確認は回答履歴のない問題を対象とする。
結果はこの回の正解数と、更新後の定着状態を分けて表示する。
途中終了時も確定済み回答は保持し、未回答は誤答にしない。

操作領域は44px以上を目安にし、色だけに頼らない正誤表示、フォーカス表示、
読み上げ用ラベルを付ける。320px・380px・1280pxで横はみ出しを確認する。

## 6. 定着度の定義（設計提案）

このアプリに登録した有効・照合済み問題を対象とする。全試験範囲の習得率ではない。
同じ問題に対する回答履歴から、以下の状態を導出する:

1. 未確認: 確定した回答が一度もない。
2. 要復習: 最新の回答が誤答。
3. 学習中: 正解したが、定着条件はまだ満たしていない。
4. 定着: 誤答を挟まず、最初の正解から24時間以上後にも正解している。

判定の詳細:
- 初回正解を基準時刻として保持する。24時間未満の繰り返し正解では定着にせず、
  基準時刻も後ろへ動かさない。回答履歴自体はすべて保存する。
- 基準時刻から24時間以上後の正解で定着にする。
- どの状態でも誤答したら要復習になり、基準時刻と定着判定を解除する。
- 誤答後の次の正解は学習中。その正解を新しい基準時刻とする。
- 初版は日数経過だけでは定着を自動解除しない。忘却曲線や合格予測は導入しない。
- 経過時間はUTC時刻差で判定する。端末時計の大幅変更は保証対象外として説明する。

定着度 = 定着した有効問題数 / 登録された有効問題数。未確認も分母に含める。
全体・カテゴリ別で同じ定義とし、割合だけでなく「定着○問 / 登録○問」を示す。
0問の場合は0%ではなく「対象問題なし」。表示は整数%に切り捨て、全問定着前に100%にしない。
追加問題による偏りがあるため、単元全知識の網羅率とは呼ばない。
新しい問題の追加で割合が下がる場合は、問題数が増えたことを通知する。
正解や内容に意味のある修正をした問題は改訂番号を上げ、新版では未確認から判定する。
旧版の履歴は過去の学習記録として残すが、新版の定着判定には流用しない。

## 7. 学習時間（設計提案）

対象は解説・教材図の閲覧、問題の検討、回答後の解説確認。ホーム、設定、
成績一覧、バックアップ操作は計測しない。解説を表示している間は操作がなくても対象とする。
「学習を一時停止」も用意し、放置時間を自分で止められるようにする。

計測は表示中かつフォーカスがあり、一時停止していない学習画面だけで行う。
`visibilitychange`、`blur`、`pagehide`で直ちに区間を閉じ、
復帰時は新しい区間を開始する。背景中の経過を復帰時にまとめて加算しない。
画面消灯・他アプリ切替時もこれらのイベントに従って停止する。

5秒以下の間隔で短い区間を保存する。区間の長さは単調時計で測り、
異常に長いコールバック間隔は全体を計上せず最大5秒に制限する。
強制終了などイベントが届かない場合、未保存の最大5秒は失われ得る。
これは実際に読んでいたことを証明する時間ではなく、アプリで計測できた学習時間。
Android実機で消灯・アプリ切替を検証し、停止しない場合はリリースを保留する。

複数タブの二重計上はWeb Locksによる単一の計測所有者で防ぐ。
ロックを得られない画面は閲覧のみ可能で、他画面で計測中と表示する。
初版の動作対象は必要APIを備えたAndroid Chromeとし、非対応なら計測不能を通知する。
区間ごとに一意IDを使い、再保存で二重加算しない。

時刻はUTCと端末のローカル日付・当時のタイムゾーン情報を保存する。
日付をまたぐ区間はその場の午前0時で分割する。
過去の記録の日付はタイムゾーン変更で付け替えない。
週は月曜から日曜、月は暦月。各集計は保存済み日別区間の合計から導出する。
秒単位で保持し、表示は分単位、1分未満は「1分未満」。丸めは合算後に行う。
保存に失敗した時間を確定済み累計に見せず、エラーと再試行を表示する。

## 8. 構成とデータ

実装技術: ブラウザ標準のJavaScript ES ModulesとCSS、IndexedDB、Service Worker / Cache Storage。
新規アプリのため依存パッケージ不要の構成に簡素化する。検証はNode組み込みテストとChromeを使う。
アプリサーバーへの学習記録送信やログインは不要。教材と利用者記録は端末内で完結する。
画面、教材検証、演習制御、定着判定、時間計測、保存、バックアップを分離する。
外部解析SDK・広告・外部フォントは使用しない。

主要データ:
| データ | 主な項目 |
| --- | --- |
| 教材パック | 安定ID、版、スキーマ版、カテゴリ、節、問題、原本対応表、アセット一覧とチェックサム |
| 解説節 | ID、カテゴリID、順序、見出し、本文ブロック、図表ID、出典、照合状態 |
| 問題 | ID、改訂、主カテゴリID、関連節ID、種別、設問、選択肢ID、正解ID、解説、出典、照合状態 |
| アセット | ID、メディア種別、Blob、サイズ、チェックサム、用途、表示用説明 |
| 回答履歴 | 一意ID、問題IDと改訂、選択肢ID、正誤、確定日時、演習IDと出題インスタンスID |
| 演習 | ID、問題と改訂の配列、順序、現在位置、選択・確定状態、開始・終了日時 |
| 学習区間 | 一意ID、開始・終了UTC、日付、タイムゾーン、計測秒数、読書/演習の区別 |
| 設定と再開位置 | 試験日、前回の節・位置、教材版、最終バックアップ日時、DBスキーマ版 |

問題の主カテゴリは1つとし、全体集計で重複計数しない。
回答履歴からの導出値はキャッシュ可能だが、集計の正は履歴と有効な教材版とする。
回答保存と演習の確定状態更新は同一トランザクションにし、一意キーで再送を排除する。
書き込み失敗時は「保存されました」と表示しない。選択状態を保ったまま再試行を案内し、保存成功までは次問へ進めない。
DB移行前の版を検査し、未知の新版や移行失敗時に既存データを初期化しない。

## 9. 初回導入・オフライン・更新

Androidは通常のLAN内HTTPではService Workerを利用できない。
Macで開けた `localhost` の画面案が、そのままスマホにインストールできるわけではない。
通常のHTTPS静的ホスティングを利用し、アプリ本体だけを配信する。
サービス名・費用・公開範囲を説明して本人の承認を得てから公開する。
独自証明書やMacからのLAN配信は使わない。教材・学習記録をサーバーへ送信しない。
配信用ディレクトリはアプリ本体の明示的な許可リストから作成し、
原本・教材パック・バックアップ・開発用ファイルは含めない。
開発プレビューはMacのlocalhostのみで行い、Androidのオフライン確認は配信後に行う。
接続先を変える場合は事前にバックアップを取り、新しい接続先で復元する。

初回はアプリ本体を取得してホーム画面に追加し、ローカル教材パックをファイル選択で取り込む。
教材パックはMacからUSB等で端末へ渡せるファイルとする。外部クラウドへのアップロードを前提にしない。
教材パック作成は開発側で行い、利用者にPDFの手作業分割を求めない。
初回準備と更新時以外はMacの起動も通信も不要にする。

Service Workerはアプリ本体を版ごとに完全取得してから有効化し、
画面遷移のオフライン起動に対応する。教材と画像はIndexedDBにまとめて保存する。
「オフライン準備完了」はアプリ本体のキャッシュと教材全ファイルの保存・整合性確認後だけ表示する。
途中失敗は準備未完了として再試行し、使える旧版を残す。
教材パックの切替は全件検証後のトランザクションで行い、不完全な版を有効にしない。
問題ID・改訂で履歴を対応させ、更新前の進行中演習は保存済み回答を残して終了扱いとする。

アプリ更新は演習中に強制反映せず、終了後に通知して再起動する。
古いアプリが読めない教材は拒否し、更新を案内する。
オフラインでは更新確認できなくても旧版で学習できる。
保存容量の見積り、利用量・空きの目安、永続ストレージ許可状況を設定に表示する。
永続化要求は行うが、許可やブラウザによる削除防止を保証しない。
容量不足で教材を壊したり記録を黙って削除したりしない。
接続先のホスト名・ポート等を変えると保存領域が変わるので、更新でも同一originを維持する。

## 10. バックアップと復元

単一のJSON形式ファイル（`.agristudy`）にスキーマ版・教材版・教材全体・
Base64画像・回答履歴・学習区間・設定を含める。ZIP依存を省いた構成とする。
別端末やブラウザデータ消去後でも、アプリ導入後にそのファイルから復元できるものとする。
ファイルは自動送信しない。著作物と個人記録を含むこと、初版では暗号化しないことを明示する。
作成中は計測を区切り、DBの一貫したスナップショットを出力する。
保存先は利用者が選び、ダウンロード生成だけで安全な外部保存が完了したとは保証しない。

復元は初版ではマージでなく全体の置換。
型・版・参照・ファイルサイズ・画像データ量・チェックサムを検証し、
HTMLやスクリプトを実行しない。未対応版・不正パックは変更前に拒否する。
件数と置換対象をプレビューし、現状のバックアップを促してから明示確認で適用する。
検証・書き込みの失敗時は元の記録を残す。成功後の進行中演習は終了状態で復元し、
過去の時間区間を「現在も計測中」として再開しない。
初版には記録の全消去ボタンやクラウド同期は設けない。

## 11. 非目標・失敗とみなすこと

初版では全教材・全過去問の取り込み、自由記述、自動採点AI、共有、ランキング、
複数端末同期、通知、学習計画の自動生成、APK配布は行わない。
1回の正解を定着と呼ぶこと、読んだ時間を知識の習得と混ぜること、
サンプル成績を本物として見せること、回答前に正解が見えること、
ネットがないと解説画像や記録が使えないこと、無断で教材を外部送信することは失敗とする。

## 12. 検証と完成条件

- 教材: 原本対応表と全解説・全例題を照合し、追加問題の正解と根拠を確認。
  画像・説明文・拡大表示に回答前の答え漏れがないことを確認する。
- 定着: 初回正解、24時間未満、24時間ちょうど、途中誤答、定着後の誤答、
  分母0、問題追加、改訂変更をテストする。
- 演習: 条件の交差、重複なし、0件・5件未満、二重送信、途中終了・再開、
  保存失敗、解説から戻る場合をテストする。
- 時間: 可視/不可視、フォーカス、一時停止、強制終了、長い停止間隔、
  複数タブ、日付・月・週の境界、時差変更、保存失敗をテストする。
- 保存: 再読み込み後の保持、教材更新の失敗・成功、互換性のない版、
  バックアップ往復、不正ファイル、容量不足時に既存記録を保持することを確認する。
- PWA: HTTPSでの初回準備とホーム画面追加後、Android Chromeで機内モードにして
  アプリを終了・再起動し、全文・全画像・演習・記録・バックアップを使えることを確認する。
  ロック解除や別アプリからの復帰時に背景時間が増えていないことを実機確認する。
- UI: 承認画面案に沿った日本語表示、320/380/1280px、タッチ・キーボード操作を確認する。

自動テストで確認したことと、実際のAndroidで確認したことを分けて報告する。
実機にアクセスできない項目は本人に手順を渡して確認を依頼し、未検証を完了と呼ばない。

## 13. 実装担当に残す裁量と進行

この設計で変えない範囲のファイル構成、コンポーネント分割、テストツール、
静的配信の手順、画像圧縮品質は実装計画で具体化する。
教材問題数は原本照合と主要知識対応表から確定し、問題数を根拠なく約束しない。
通常のHTTPSサイトからの導入手順と、教材の端末内読み込みを実装計画・実機検証に含める。

順序は、設計の点検、本人による設計承認、実装計画、テストを伴う実装、
教材照合、オフライン・実機確認。承認前には製品の作成や依存関係の導入をしない。
現在このフォルダはGit管理されていないため、設計書はファイルとして保存する。
後にGit管理する場合、原本・教材派生物・バックアップ・鍵・`.superpowers/`の
意図しない追跡や公開を防ぐ設定を先に行う。
